# 小陪微信小程序

这是与 `Fibocom_Xiaopei` 板端服务配套的原生微信小程序。页面只调用仓库已存在的接口，不将尚未实现的远程监护、位置跟踪或移动控制伪装成可用功能。

## 已实现的界面与能力

| 页面 | 小程序能力 | 对应板端接口 |
| --- | --- | --- |
| 今日 | 在线状态、当前情绪、专注状态 | `GET /api/status` |
| 陪伴 | DeepSeek 文本对话、让设备播报回复 | `POST /api/chat`、`POST /api/tts` |
| 专注 | 开始/结束专注 | `POST /api/command`（`study` / `stop`） |
| 心情 | 五种情绪自评 | `POST /api/mood` |
| 小陪 | ASR、TTS、视觉状态；状态/休息/继续指令 | `GET /api/status`、`POST /api/command` |

仓库同时具备本地账号会话、摄像头人脸/表情识别、板载 Whisper Tiny 语音识别、板载 TTS、日程提醒、主动关怀和本地记忆。日程提醒与账号登录的交互尚未放入本期小程序：它们需要先补齐面向小程序的安全鉴权和日程增删改 API，避免在客户端暴露设备服务。

## 首次导入与本地预览

1. 打开微信开发者工具，选择“导入项目”。
2. 项目目录选择本文件所在目录；开发阶段可使用测试号或在 `project.config.json` 填入小程序 AppID。
3. 在 `app.js` 的 `apiBaseUrl` 填入网关地址。必须为 HTTPS，并在微信公众平台的“开发管理 → 开发设置 → 服务器域名”配置为合法 request 域名。
4. 开发者工具的“详情 → 本地设置”仅可暂时关闭合法域名校验进行本地联调；真机和提交审核前必须恢复 HTTPS 域名配置。

## 上线前必须完成的服务端工作

板端默认服务运行在 `http://127.0.0.1:5004`，不能直接被小程序访问。应在受控服务器或局域网网关中完成：

1. 以 HTTPS 反向代理转发至板端 `5004` 服务，且不要把开发板直接暴露到公网。
2. 为小程序设计 token/会话交换；现有服务依赖浏览器 Cookie，`wx.request` 不应直接复用为正式鉴权方案。
3. 对 `/api/chat`、`/api/tts`、`/api/command` 做用户绑定、频率限制、输入审计和访问日志。
4. 如果要在小程序中加入语音输入，应由小程序录音后调用已有 `/api/asr`，并补充录音授权说明、文件大小限制和失败重试。

## 微信提交包清单

提交到微信开发者工具的是整个本目录：`app.json`、`app.js`、`app.wxss`、`project.config.json`、`sitemap.json`、`pages/` 和 `services/`。另外需要在公众平台准备：正式 AppID、类目与主体资料、HTTPS 业务域名、隐私保护指引（收集的昵称/账号、对话文本、录音、摄像头画面或情绪推断等）、测试账号/审核说明、版本号与提审说明。

> 摄像头、人脸和情绪属于高度敏感场景。正式版应默认关闭，获得单独、清晰的授权后才启用；不得将情绪识别结果作为健康、心理或安全结论。

## 版本边界

参考图中的“家庭守护、家人状态、宠物状态、移动方向控制”不在当前 `Fibocom_Xiaopei` 的 API 或设备能力范围内，因此未实现。后续如果新增设备端数据采集、授权关系和相应 API，再设计这些模块。
